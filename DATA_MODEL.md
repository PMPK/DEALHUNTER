# Data model

TypeScript types: `src/domain/types.ts`. Data: `src/data/*.json` (no UI imports). Validation: `src/domain/validate.ts`
(run in tests and logged in dev).

## Provenance (shared by every assessment)
```
confidence          0..1   editorial scale, shown as Low / Medium / High
reasons[]           why this value
evidence[]          { label, url?, note? }
lastUpdated         YYYY-MM-DD
verificationStatus  verified | unverified | disputed
```
Rule: `verified` requires at least one evidence entry with a `url`.
`ScoredItem = Provenance + score (0..100 | null)`; `null` renders as "n/a", never as a low score.
`effectiveStatus()` shows a tester's "Wrong" as *disputed*; positive feedback never upgrades to *verified*.

## Entities
| Entity | File | Key fields |
|--------|------|-----------|
| Area | `areas.json` | id, name, center, summary, `scores{overall,beach,infrastructure}: ScoredItem`, positives, negatives, `warnings[]: RealityWarning`, suitableFor |
| RealityWarning | in area | id, severity (info/caution/problem), title, detail + Provenance |
| Zone polygon | `zones.geojson.json` | GeoJSON Polygon, `properties.areaId`. **Schematic**, generated by `tools/generate-zones.mjs`, not an official boundary |
| Attraction | `attractions.json` | id, name, coordinates, coordinatesApproximate, category, rating (null = unknown), description, source, verificationStatus, lastUpdated |
| Hotel | `hotels.json` | id, areaId, name, `synthetic: true` (type-enforced), coordinates, style, note |
| DemoOffer | `offers.json` | id, hotelId, `demo: true`, price, people, departureCity, dates, nights, board, `dealScore: null` |
| Airport | `meta.json` | name, iata, coordinates (distance = straight-line, computed) |
| FeedbackEntry | localStorage `zanzibar-reality:feedback:v1` | areaId, rating (accurate / mostly-accurate / wrong / not-sure), note, updatedAt |

## Feedback export (`zanzibar-reality-feedback` v1)
```json
{ "schema": "zanzibar-reality-feedback", "schemaVersion": 1, "exportedAt": "...", "datasetVersion": "0.1.0-seed",
  "entries": [{ "areaId": "paje", "areaName": "Paje", "rating": "wrong", "note": "...", "updatedAt": "...",
                "seed": { "overall": 74, "beach": 56, "infrastructure": 76, "verificationStatus": "unverified" } }] }
```
`seed` records what the dataset claimed at judgement time so corrections can be diffed.

## Adding an area
1. Add an object to `areas.json`.
2. Add `[id, centre, lengthKm, widthKm, bearing]` to `tools/generate-zones.mjs`, run `node tools/generate-zones.mjs`.
3. `npm test` (validation + zone no-overlap checks).

## Score bands
Strong ≥70 (green ▲) · Mixed 50–69 (yellow ◆) · Weak 30–49 (orange ▼) · Poor <30 (red ✖) · Unknown (grey ?).
